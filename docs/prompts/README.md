# AI 辅助开发流程与提示词

本目录定义 LaFiDemo 使用 AI 编码工具时的标准交付顺序、阶段门禁和可复用提示词。目标是提高需求到交付的速度，同时保留人工决策、代码审查和生产质量责任。

## 文档

- [`workflow.md`](workflow.md)：从需求到上线的流程、分支策略、阶段输入/输出和质量门禁。
- [`prompt-library.md`](prompt-library.md)：各阶段可以直接复制并填写的提示词模板。

## 推荐处理顺序

```text
Issue / 用户需求
  → 需求澄清与影响分析
  → PRD / 验收标准
  → 领域与系统设计
  → 方案评审 / ADR
  → 拆分任务与分支
  → 编码实现
  → 自动化测试与安全检查
  → PR / 人工 Review
  → CI 通过
  → 预发布验证 / 发布与回滚准备
  → 线上观测 / 复盘
```

每个阶段先产出可审查的工件，再进入下一阶段。AI 负责分析、草拟、实现和验证辅助；产品范围、架构取舍、安全风险、合并和上线由有权限的人员最终确认。不要让 AI 跳过需求/方案评审直接“全自动完成”高风险电商功能。

## 使用约定

1. 每次开始新任务，先让 AI 阅读仓库根目录 `AGENTS.md`，以及相关 `docs/rules/`、架构、技术选型和数据库蓝图。仓库现有代码和锁定依赖优先于通用假设。
2. 未知信息必须列为问题或明确标注假设，不得编造业务规则、官方版本兼容性、测试结果或仓库中不存在的文件。
3. 默认先只读分析；只有用户明确要求实现后才改代码。高风险事项（支付、退款、库存、租户权限、破坏性迁移、生产配置）必须先给出设计和风险，由人确认后再实施。
4. 需求范围以批准的 PRD / Issue 验收标准为准。发现范围冲突、隐私/安全问题或不可逆数据变更时暂停并报告。
5. 所有代码输出都要包含修改文件、设计理由、运行过的检查及未执行项。没有实际执行的测试不能说“通过”。
6. 一个分支/PR 聚焦一个可验证变更；AI 不得直接向受保护主分支推送或自行批准/合并/发布。

详细流程与阶段质量门禁见 `workflow.md`；可复制的阶段提示词见 `prompt-library.md`。
